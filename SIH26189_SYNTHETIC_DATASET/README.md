# SIH26189 — AI-Powered Criminal Network Analysis System
## Synthetic Dataset (Ministry of Home Affairs)

**SYNTHETIC_DATA = TRUE.** Every person, organization, phone number, bank account,
vehicle registration, address, FIR, and case in this dataset is entirely fictional,
generated by `generate_sih26189_dataset.py` with `RANDOM_SEED = 26189`. No real
individuals, organizations, phone numbers, bank accounts, vehicle registrations,
addresses, or criminal cases are used or referenced anywhere in this dataset.

## 1. SIH problem alignment

SIH26189 asks for an AI system that can "automatically analyze structured and
unstructured crime-related data to uncover criminal networks, identify key
influencers, detect suspicious patterns, and provide actionable intelligence for
investigators." This dataset is built to exercise every stage of that pipeline:

```
MULTI-SOURCE DATA -> ENTITY EXTRACTION -> ENTITY RESOLUTION -> RELATIONSHIP DISCOVERY
-> GRAPH CONSTRUCTION -> INFLUENTIAL PERSON DETECTION -> SUSPICIOUS PATTERN DETECTION
-> CROSS-CASE ANALYSIS -> TEMPORAL/SPATIAL ANALYSIS -> EVIDENCE TRACEABILITY
-> INVESTIGATIVE INSIGHT
```

Data is deliberately **fragmented across sources** (FIR narrative, CDR, financial
records, surveillance, social media, criminal history, intelligence reports) so a
prototype system must integrate multiple weak signals rather than read an answer
off any single table.

## 6. Graph architecture

`graph/graph_edges.csv` exports every relationship as a typed edge
(`source_id, source_type, target_id, target_type, edge_type, timestamp, weight,
confidence, source_record_id`). Node types: `PERSON, ORGANIZATION, PHONE, ACCOUNT,
VEHICLE, LOCATION, CASE, EVENT`. Representative edges: `PERSON--USES-->PHONE`,
`PERSON--OWNED-->BANK_ACCOUNT`, `PERSON--OWNED-->VEHICLE`, `PHONE--CALLED-->PHONE`,
`PERSON--TRANSFERRED_MONEY-->PERSON`, `PERSON--MEMBER_OF-->ORGANIZATION`,
`PERSON--APPEARED_IN_CASE-->CASE`.

## 7. Hidden multi-hop networks & the flagship A→B→C→D→E case

**Network `NET_001` / Case `CASE_0001`** is the flagship demonstration.

- `PERSON_1476` (role `UPSTREAM_COORDINATOR`) never appears at the crime/event
  location and does not have the highest call or transaction volume in the raw data.
- The chain `PERSON_1476 -> PERSON_0026 -> PERSON_0397 -> PERSON_0405 -> PERSON_1459` is embedded as CDR calls roughly 6-18
  minutes apart in the ~2 hours before the incident, then a reverse chain in the
  ~1-2 hours after, plus recurring weaker coordination calls over the preceding
  weeks, a layered financial trail, vehicle movement toward the incident location
  for the final actor, one surveillance sighting, one identity-resolution
  ambiguity, one innocent high-degree contact, one false-positive pair, and one
  cross-case shared-entity link.
- `ground_truth/ground_truth_orchestrators.csv` records `PERSON_1476` with
  `reason_code = MULTI_HOP_TEMPORAL_CHAIN`. Expected system output: *"Potential
  upstream coordinator — high-confidence multi-hop temporal association — requires
  verification"* — never a certainty/guilt claim (see Section 13).

11 further networks embed the remaining multi-hop patterns (A→B→C→event,
A→B→C→D→event, convergent structures, branching structures, and broker-fan-out
structures where the coordinator never talks directly to operational members).
See `metadata/scenario_catalogue.csv` for the full catalogue (scenario types:
`ENTITY_RESOLUTION, HIDDEN_NETWORK, MULTI_HOP_COORDINATION, INFLUENTIAL_PERSON,
BROKER_DETECTION, SUSPICIOUS_TRANSACTION, SUSPICIOUS_COMMUNICATION, CO_TRAVEL,
CROSS_CASE_LINK, FALSE_POSITIVE, TEMPORAL_PATTERN, NLP_ENTITY_EXTRACTION`).

## 8. Influential-person scenarios

Roles are assigned so that **influence is not reducible to raw degree**:
`UPSTREAM_COORDINATOR` (few direct edges, sits upstream in the temporal chain),
`BROKER` (connects otherwise-separate clusters), `HIGH_DEGREE_INFLUENCER` (many
edges, genuinely central), `HIGH_DEGREE_INNOCENT` (many edges but mostly
legitimate contacts — a deliberate trap for naive centrality-only models),
`FINANCIAL_FACILITATOR`, `RECRUITER`, `OPERATIONAL_MEMBER`, `PERIPHERAL_ASSOCIATE`,
`INNOCENT_CONTACT`. See `ground_truth/ground_truth_influencers.csv` and
`ground_truth/ground_truth_roles.csv`.

## 9. Suspicious-pattern & false-positive scenarios

- **45 false-positive pairs**: family members, coworkers,
  business partners, taxi/delivery contacts with frequent calls and/or transfers
  but `ground_truth_status = INNOCENT` or `FALSE_POSITIVE`
  (`ground_truth/ground_truth_suspicious_patterns.csv`).
- **55 strong + 110 weak co-travel pairs** and
  **50 innocent co-location pairs** sharing routes/stops with
  zero direct CDR contact — tests spatiotemporal reasoning independent of
  communication data.
- **26 alibi/location contradictions**, some criminal, some
  innocently explainable (`explainable_innocently` flag).
- **65 same/similar-name entity-resolution traps** across different
  cities, phones, accounts, and vehicles.
- **32 cross-case links**: entities silently shared across
  otherwise unrelated cases, never explicitly labelled in the raw tables
  (`ground_truth/ground_truth_case_links.csv`).

## 10. Unstructured text for NLP/NER

`fir_records.narrative`, `surveillance_reports.observation`,
`social_media_records.content`, and `intelligence_reports.observation` contain
natural-language text referencing people (sometimes by alias/abbreviation),
locations, vehicles, and organizations — e.g. *"A male individual resembling R.
Sharma was observed near LOCATION_0042"* — designed for downstream NER/entity-
linking experiments where the reference is not trivially resolvable to a
`person_id` without cross-source corroboration.

## 11. Evidence, reliability & provenance

Every relationship traces to a `source_record_id`; `evidence.csv` links case-level
conclusions back to raw CDR / transaction / surveillance / social-media /
intelligence / FIR records with a `reliability` score drawn from source-specific
bands (official structured records 0.90-0.99, transactions 0.90-0.98, CDR
0.85-0.97, ANPR/vehicle 0.80-0.95, cell-tower/location 0.60-0.85, surveillance
0.60-0.90, social media 0.40-0.85, unverified intelligence 0.30-0.70).
`ground_truth_status` on evidence and relationships (`CONFIRMED, LIKELY, WEAK,
INNOCENT, FALSE_POSITIVE, UNKNOWN`) makes clear that **intelligence is evidence,
not automatically truth**.

## 12. Train / validation / test split

Split **by criminal network / case**, not by row, to avoid leakage — an entire
network's persons, calls, transactions, and evidence live in exactly one of
`train/`, `validation/`, or `test/`. `metadata/validation_report.json` confirms
`leakage_checks.status = "PASS"`. Split sizes: 8 networks train /
2 validation / 2 test (~70/15/15), standalone cases split
the same way.

## 13. Important interpretation rule

The dataset intentionally does **not** encode "high centrality = criminal." The
`HIGH_DEGREE_INNOCENT` role, the false-positive pairs, and the innocent
co-location pairs all exist to punish that shortcut. A system built on this
dataset should produce investigative language such as *"potential influential
individual," "potential coordinator," "suspicious association," "high-confidence
relationship — requires verification"* rather than declarations of guilt.

## 16. Loading the graph into Neo4j

```
// after copying graph_edges.csv (and persons.csv/organizations.csv/vehicles.csv/
// bank_accounts.csv for node properties) into Neo4j's import/ directory

LOAD CSV WITH HEADERS FROM 'file:///persons.csv' AS row
MERGE (p:PERSON {id: row.person_id}) SET p.name = row.name, p.city = row.city;

LOAD CSV WITH HEADERS FROM 'file:///graph_edges.csv' AS row
MATCH (s {id: row.source_id}), (t {id: row.target_id})
CALL apoc.create.relationship(s, row.edge_type, {
  weight: toFloat(row.weight), confidence: toFloat(row.confidence),
  timestamp: row.timestamp, source_record_id: row.source_record_id
}, t) YIELD rel
RETURN count(rel);
```

(Node labels/properties can be enriched similarly from `organizations.csv`,
`vehicles.csv`, `bank_accounts.csv`, `cases.csv`.)

## 17. Example investigation queries

- *Who is connected to `PERSON_1476`, and through what evidence?*
  → filter `relationships.csv` on `source_entity_id`/`target_entity_id`, then join
  `evidence.csv` on `supports_relationship`.
- *Is there a path from `PERSON_1476` to the crime location in
  `CASE_0001`?* → traverse `graph_edges.csv` (BFS/shortest-path) from
  `PERSON_1476` to `PERSON_1459`.
- *Which two cases share a hidden entity?* → join `ground_truth_case_links.csv`
  (evaluation only) or discover independently via shared `phone_id` / `vehicle_id`
  / `account_id` across `relationships.csv` and `evidence.csv`.
- *Who are the brokers connecting otherwise-separate communities?* → run community
  detection on `graph_edges.csv`, then look for high-betweenness, low-degree nodes.
- *Does this person's claimed alibi hold up?* → compare `fir_records.narrative` /
  `surveillance_reports.observation` against `location_events.csv` and
  `vehicle_events.csv` timestamps for the same entity.
